摘要

我们研究一个具体问题：仅由历史时间序列预测的离散方向信号，能否提高多变量时间序列的数值预测精度？围绕 ETTh1，我们开展三个互补实验。首先，使用启用推理的 DeepSeek-v4-pro 预测每个变量的三分类方向标签，完成原训练、验证和测试集的标签覆盖。其次，将预测标签接入五种时序模型，比较直接替换 Oracle 条件、使用预测条件重新训练、真实条件 Oracle 和无条件基线。最后，在固定 Oracle 模型上人为控制标签正确率，评估模型对随机错误的敏感性。结果表明：测试集 L1/L2 Macro-F1 分别为 0.3517/0.4758；直接替换在全部 20 个配置上均劣于原始基线，重训虽在 18 个配置上缓解退化，但未产生稳定的额外标签收益。随机误标实验中，四种方案的平均 MSE 均随正确率提高而下降，90% 档位优于基线、80% 档位劣于基线。本报告将这些结论限定为单数据集、单训练种子和单噪声种子的实证观察，不将随机误标结果解释为 LLM 的部署准确率门槛。

关键词：时间序列预测 · 大语言模型 · 条件预测 · Oracle 分析 · 标签噪声 · 负结果

1研究问题与统一实验设置

本报告的三项工作是同一研究框架下的三个实验，而非三个独立预测模型：实验一测量方向信号的可预测性，实验二测量其下游效用，实验三测量固定预测模型对标签错误的敏感性。先前已完成的 Oracle 与原始基线作为共同参照，本轮不重复训练这些参照。

RQ1 · PREDICTABILITY

方向标签能否预测？

评价：Macro-F1、Accuracy

RQ2 · DOWNSTREAM UTILITY

预测标签是否有用？

1.1 数据、任务与评价单位

所有实验使用 ETTh1 的原始时间切分，7 变量输入、7 变量输出；输入历史长度 T = 512，预测长度 H = 64。原训练、验证和测试集分别包含 8,065、2,817 和 2,817 个有效窗口。原始目标起点分别为 512–8576、8640–11456 和 11520–14336（从 0 计数，含端点）。数值模型沿用仅由原训练集拟合的 StandardScaler。

五个配置为 DLinear、PatchTST、iTransformer、FreTS 和 iTransformer+FreDF；其中 FreDF 是沿用的 iTransformer 频域损失配置，而非另一个基础架构。主表先对各模型的所有测试窗口、预测步及 7 个变量计算 MSE，再对五种模型等权平均。OT 另行报告；全变量提升不等于 OT 一定提升。

MSEm = (NHC)−1 ∑n=1…N ∑h=1…H ∑c=1…C (ŷn,h,c − yn,h,c)2
MSEavg = ⅕ ∑m=1…5 MSEm
所有数值指标均在原标准化空间计算；MSE / MAE 越小越好。主表不是相对改善率的平均。

1.2 两种模型无关的方向标签

令 t 为预测区间第一步，μFt,c 为未来 64 步均值，μRt,c 为最近历史 64 步均值，μXt,c 和 σXt,c 为历史 512 步均值和总体标准差（ddof = 0）。两种标签均不依赖任何基础模型的预测。

rL1t,c = (μFt,c − μRt,c) / max(σXt,c, ε)
rL2t,c = (μFt,c − μXt,c) / max(σXt,c, ε)
z(r) = +1，r > τ；　z(r) = −1，r < −τ；　其余 z(r) = 0
本轮固定 τ = 0.5、ε = 0.001。0 表示均值变化处于阈值内，不表示未来曲线没有波动。
真实标签需要未来数据，因此只能用于离线评分或明确标注的 Oracle 实验。LLM 推理输入不含未来值；方向标签的 Accuracy 也不是未来每一步数值变化方向的准确率。

2实验一：历史条件下的方向标签预测

2.1 设计与执行

通过服务器 DAO API 调用 aliyun/DeepSeek-v4-pro，启用推理，使用冻结的 pro-concise 提示词。输入包含历史时间序列及历史派生信息，输出每个变量的 L1、L2 三分类判断；不臆造变量语义或因果关系，不用未来统计量辅助请求。前期完成了接口连通性、输出长度、格式和提示词的开发检查，最终版本在测试集上不再调整。

为降低调用量，采用因果组首复用：每个切分内，每 32 个连续窗口共用第一个窗口的预测标签；后续窗口只能复用先前已获得的判断，不跨切分。训练、验证、测试分别有 253、89、89 个代表窗口，共 431 个有效代表窗口，覆盖 13,699 个窗口及 95,893 条窗口×变量记录。评分覆盖全部窗口，而非只评估代表窗口。

训练期 API 输入的归一化只拟合截至当前代表窗口的已观测训练前缀；验证和测试使用完整原训练集统计。这个 API 输入变换与下游数值模型固定的原训练集 scaler 分开管理。真实未来仅用于离线标签评分。

2.2 结果与解释

L2 的测试 Macro-F1 为 0.4758，高于 L1 的 0.3517，但两者均未达到最初希望的 0.5。L2 从验证集 0.6049 下降到测试集 0.4758，因此不能以验证结果替代泛化成绩。所有标签均有效，但输出完整性不等同于预测有效性。

测试集恒预测 0 的参照准确率为 L1 74.78%、L2 72.68%，高于 LLM 的 68.32% 和 62.01%；其 Macro-F1 仅为 0.2852 和 0.2806，低于 LLM。因而 LLM 获得了一定三类区分能力，但整体准确率与 Macro-F1 呈现不同结论，应同时报告。

发现 1：历史条件下的三分类预测流程已跑通并完整覆盖三段数据，但当前版本的测试标签质量仍有限。分类成绩本身不能证明下游数值预测收益。

模型接收七个变量各 512 个历史值（保留四位小数），以及历史均值、最近 16/64/128 步均值、历史总体标准差、32 个连续 16 步块均值和四个分类边界。完整历史始终保留，统计摘要只是补充。边界完全由历史计算，不包含真实未来均值。模型需要用同一个未来均值判断 L1 与 L2，避免两种标签在数值上相互矛盾；0 表示落入中间区间，不表示“不确定”。

3实验二：LLM 标签的下游预测效用

3.1 两种接入机制与 2 × 2 设计

A · 联合条件预测头

在原模型输出相关特征处加入条件头。骨干与条件头共同训练，使用每个变量自己的标签。G2-A 从与旧 Oracle 对应配置相同的初始化开始，不从已训练的 Oracle 权重微调。

B · 冻结骨干校正模块

加载原无标签基线并冻结参数及 buffers，只训练共享的逐变量校正模块。模块使用原预测、最近 64 步历史及该变量的方向标签，输出长度 64 的校正量。

A：hc → [hc, Emb(zc)] → 条件残差 → 原模型输出变换
B：ŷc = fθ₀(X)c + gφ([fθ₀(X)c, Xrecent,c, Emb(zc)])
A 为概念性接入表示：具体残差位置随骨干而异，保留其原有输出变换；B 的 θ₀ 完全冻结。

条件模块采用三类 embedding（维度 8）、宽度 32 的隐藏层、GELU 和 64 维输出，末层零初始化。A/B 分别使用 L1 或 L2，共四方案；不会将 L1 和 L2 同时输入一个模型，也不将其他变量的未来标签输入当前变量的条件头。

3.2 结果与对照解释

直接替换条件后，G1 的 20/20 个配置 MSE 均差于 G4。G2 在 18/20 个配置上优于 G1，但仅 6/20 略优于 G4，且相对匹配的 zero 对照只有 7/20 改善。四个方案的五模型平均 MSE 均未超过原始基线；B-L1 重训最接近基线。

必须区分架构/训练路径本身的影响与标签信息的影响。DLinear-A 的 G2-L1/L2 MSE 为 0.426923 / 0.426023，而 A-zero 已为 0.426912，原始基线为 0.353263。大部分差距在零标签条件下同样存在，不能将其全部归因于 LLM 标签错误。另一个例子是 iTransformer B-L1：G2 的全变量 MSE 略有改善，但 OT MSE 比原始基线恶化 18.42%。

发现 2：用预测标签重训通常比直接替换更稳妥，但本轮没有建立稳定的额外标签收益。G2 接近基线，不等价于 LLM 条件带来了有效增益。

4实验三：受控标签错误敏感性

4.1 固定权重、仅干预测试标签

为研究标签错误与数值损失的关系，冻结原 Oracle checkpoint，仅在测试时将一定比例的真实标签替换为错误类别。正确率设为 60%、70%、80%、90% 和 100%；四个非完美档位新增 5 × 4 × 4 = 80 次推理，100% 复用原来的 20 份 Oracle 结果。不训练噪声适配模型，不调用 LLM。

z̃t,c = zt,c，若 (t,c) ∉ Sq
z̃t,c ∼ Uniform({−1,0,+1} ∖ {zt,c})，若 (t,c) ∈ Sq
q 为错误率，正确率为 1−q。被选中的标签一定错误，不会随机抽回原标签。

采用固定噪声种子 20261019，逐变量无放回抽取窗口。10%、20%、30%、40% 的错误位置为嵌套集合，同一位置使用固定错误类别；所有模型、A/B 和 L1/L2 共用位置与类别偏移，以减少比较中的随机差异。每个变量有 2,817 个测试标签，实际错误数分别为 282、563、845、1,127，正确率因整数取整略偏离标称值。

4.2 结果与适用范围

四条平均曲线均随正确率增加而下降。在已测试的离散档位中，90% 正确率的四种方案均优于基线 0.368701，80% 均差于基线。该观察不能给出精确临界正确率，也不能说明所有单模型或变量具有相同阈值。

关键区别：随机误标实验针对每个窗口分别加入错误，不采用 LLM 的每 32 窗口标签共享。随机对称错误与 LLM 的结构性错误在类别混淆、变量分布、时间相关性和窗口难度上可能不同。因此，不能把这条曲线直接解释为“LLM 达到 90% 准确率就一定有效”。
发现 3：固定 Oracle 模型对标签错误敏感。该实验给出受控随机错误下的性能响应，而不是对真实 LLM 错误机制的因果归因。

5综合讨论与局限性

三个实验共同区分了信号是否可预测、信号是否有用、系统能否容忍信号错误。Oracle 结果支持方向信息具有改善平均预测的潜力；当前 LLM 标签尚未将这种潜力转化为稳定收益。重训缓解直接替换的退化，与训练/测试条件分布适配的解释相容，但该解释并未通过独立消融得到确认。

  1. 有限实验范围。只有 ETTh1、一个训练种子协议和一个噪声种子；窗口高度重叠，不能将窗口数量当作独立实验重复数。未报告显著性检验或置信区间。
  2. 测试使用边界。验证集参与了提示词开发；下游实验前已经观察到测试标签 F1，但本轮冻结模型配方、提示词、阈值和数据切分，没有据此调参。随机误标实验属于已观测测试集上的诊断。
  3. Oracle 不是部署结果。G3 和实验三均使用真实未来构造标签；Oracle 也不保证每个有限训练配置、每个变量都构成严格数学上界。
  4. 准确率不足以描述错误。类别比例、±1互相错判与错判为0、误差持续时间、窗口难度和变量权重都可能影响数值损失。本轮尚未分离这些因素。
  5. 复现协议保留。历史骨干/CPU初始化为2021，条件模块为2022，实际CUDA随机状态为2022；已披露历史包装器的RNG行为，没有在本轮静默修复以改变配对条件。

后续值得验证的问题包括：按类别与时间结构分解 LLM 错误、匹配 stride32 的噪声对照、历史分类器参照及多种子重复。这些是研究建议，并非已经执行的实验。
